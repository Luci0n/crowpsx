    Lighting & retro controls

    Color Adjustment#

    Pre-lighting controls affect source Albedo before direct/indirect lighting. Post-lighting controls grade the final combined output. The bake toggle determines whether pre-lighting color correction is exported through the material meta pass.

    Lighting#

    Every lit surface, Nature and Vertex Painting shader has three Realtime Lighting Modes, plus direct and indirect intensity, ambient/probe intensity, minimum light, stepped lighting and final posterization. The Terrain shader offers Pixel and Vertex.

    • Pixel: lighting, falloff and shadows are all calculated per pixel, like a standard Unity material.
    • Vertex: the classic PS1 look. All realtime lighting, including each light's falloff, is calculated at the mesh vertices and blended across the triangle. It is unshadowed by default; Main Light Shadows adds the main directional light's shadow where the pipeline allows it (see below).
    • Vertex Hybrid: each light's shading, including PBR highlights, is calculated at the vertices, but its falloff and shadow are applied per pixel. You keep the vertex-lit look with clean light pools and crisp shadows. Each light is shadowed only by itself, so the sun's shadow never darkens a point or spot light.

    Use ordinary Unity Lights. Their color, intensity, range, cone, culling mask and render mode are all respected, and no extra components, materials or setup are required.

    Light limits. Vertex mode receives up to eight lights per object; CrowPSX picks the most important automatically (Important before Auto before Not Important, then the brightest and closest). On URP Forward, the URP asset's Per Object Limit for additional lights applies instead. In Vertex Hybrid, the four most important point and spot lights get per-pixel falloff and shadows; any beyond that are lit fully per vertex, like Unity's Not Important lights.

    Shadows by pipeline.

    Built-in URP Forward URP Forward+ / Deferred+
    Pixel All lights All lights All lights
    Vertex Unshadowed Main light (with Main Light Shadows) Unshadowed
    Vertex Hybrid All lights All lights Main light only

    In Vertex mode on Built-in and URP Forward+, all eight lights are blended into one value, so a single light's shadow cannot be separated out. In Vertex Hybrid on URP Forward+ and Deferred+, point and spot lights come from CrowPSX's own light list, which has no access to URP's shadow maps.

    Batching. In Vertex mode on Built-in and URP Forward+, and in Vertex Hybrid on URP Forward+, each object receives its light selection through per-renderer data. GPU instancing still works, but those objects are not batched by the SRP Batcher. URP Forward uses Unity's own light lists and keeps SRP Batcher compatibility.

    Retro Geometry#

    Pixel snapping, affine warp, near-camera reduction, and optional snapped shadow casting. The visible VR / Stereo Comfort group provides Off, Comfort, Balanced, and Full profiles plus independent VR Snap and VR Affine strengths. Stereo rendering uses one shared snap displacement for both eyes to preserve binocular disparity across Multi-Pass, Single Pass Instanced, and Multiview.

    Outline#

    The six mesh-surface shaders (Default, Lite, PBR, and their Vertex Painting variants) provide an optional inverted-hull silhouette. Width can stay fixed in screen pixels or use physical world units, and an optional start/end distance fade shrinks and fades it out. A UV-transformable texture mask (luminance/R/G/B/A, optionally inverted) controls where the hull appears. Match Base Color blends toward the actual sampled surface color, including the blended layer result on Vertex Painting materials. The hull follows CrowPSX vertex wobble. Disabled materials have the outline pass switched off and submit no outline draw; enabled materials add one outline draw.

    The hull is never moved to a second renderer. The outline pass is ordered after the surface pass inside one material and relies on the depth that pass wrote, and nothing guarantees that ordering between two separate renderers.

    Transparent surfaces cannot reliably occlude their own hull because they normally do not write depth; Opaque or Cutout is recommended. Nature is intentionally excluded: its common single-plane alpha cards need texture-silhouette dilation rather than an inverted hull.

    Built-in draws the hull as part of its forward queue, the pass is tagged LightMode = Always, which that pipeline renders unconditionally and late enough to sit on top of opaque geometry. Nothing to set up.

    Universal renders only the tags its passes ask for, and the hull must be drawn after the opaque queue so the geometry that should occlude it has already written depth. It therefore carries its own LightMode = CrowPSXOutline and is drawn by a CrowPSX pass at BeforeRenderingTransparents, requested one of two ways:

    • CrowPSX Outline Feature on a Universal Renderer covers every camera using that renderer.
    • CrowPSX Outline Support on a camera covers one scene without touching any project asset, which is what lets a scene ship with outlines that work on import. It adds the URP-only injector at runtime and does nothing under Built-in.

    Using both is safe: the feature stands down for any camera the injector already covered. The pass records both ways, so it draws under Unity 6's Render Graph and under Compatibility Mode alike, as well as on URP versions that predate Render Graph entirely. Riding one of URP's own tags instead is a tempting shortcut and does not work, SRPDefaultUnlit is requested ahead of UniversalForward, so the hull would be drawn before the geometry that occludes it and overwritten by the opaque draws that follow.

    Code toggling the outline at runtime has to set both LightMode names through Material.SetShaderPassEnabled, which matches on that tag, alongside the _OutlineEnabled property.

    Outline normals (Baked Smooth UV4)#

    Hard edges are duplicated vertices. A cube corner is three vertices at the same position, each carrying its own axis-aligned normal, so an inverted hull extrudes each face along a different axis and comes apart into disjoint quads. On screen that reads as short strokes floating near the corners while the rest of the silhouette is missing. Rounded meshes hide the problem, because a smooth normal field still closes the hull.

    Smoothing the mesh's own normals would fix the hull and flatten the shading with it. Normal Source > Baked Smooth UV4 instead uses a second set of normals that only the outline pass reads.

    What the bake produces. CrowPSX copies the mesh, groups vertices that share a position, averages their distinct normals, and writes the result to UV4, TEXCOORD3 in the shaders. Welding is positional, with a tolerance scaled to the mesh bounds. Positions, lighting normals, vertex colors and lightmap UVs are untouched, so shading is unchanged; the extra channel is read only while Normal Source is set to Baked Smooth UV4, and ignored everywhere else.

    How the normal is stored. Not as an object-space direction, but as coordinates in each vertex's own tangent frame, flagged by w = 2. Static batching and GPU skinning rewrite NORMAL and TANGENT into another space while copying UV channels through verbatim, so a direction parked in UV4 would quietly stop matching the geometry it belongs to the moment either applied. Tangent-frame coordinates travel with the basis and stay correct in both cases. Tangents are generated on the generated copy when the source mesh has none, since the encoding needs them; a vertex whose tangent is still unusable falls back to an object-space direction flagged w = 1, which the shaders also read, that is the encoding meshes baked before this change carry, and the inspector flags them so they can be baked again.

    Baking and restoring. In the material inspector, Source Renderer defaults to the selected object's renderer and only appears while Normal Source is Baked Smooth UV4. Bake Outline Normals bakes that renderer in place: the generated mesh is assigned to it and its materials are switched to Baked Smooth UV4. Restore Source Mesh puts the recorded original back without deleting the generated asset. Below the buttons the section reports which mesh is being drawn, or warns that it has no UV4 or carries the older encoding. Tools > CrowPSX > Outline Normals runs the same two actions across every MeshFilter and SkinnedMeshRenderer under the current selection.

    Generated assets. Each mesh is written beside its source model as <model>_<mesh>_OutlineNormals.asset. Two labels record the original mesh reference and the source's dependency hash. Restore resolves the original through the first; re-baking reuses the existing asset when both still match, and updates that same asset in place when the model changed, so bake/restore cycles never accumulate numbered duplicates.

    Requirements and limits. Meshes need Read/Write enabled in the model importer. Only imported mesh assets can be baked: the generated copy is saved beside its source model, so a scene-only or procedural mesh has nowhere to be written and no stable identity for Restore to resolve, and the baker refuses it rather than putting the asset somewhere else. Welding is purely positional, so surfaces that merely touch are averaged together, which closes the hull across them whether or not that was intended.

    Rendering#

    Opaque/Cutout/Transparent modes; source alpha and separate Alpha Map; Bake Transparency Map; alpha contrast/power/bias, clipping, and dithering; Cull, Z Write, Z Test, depth bias, queue, stencil, and GPU instancing.

    Grunge and Emission#

    Available only on shaders that declare the corresponding properties. The inspector hides unsupported sections automatically.

    The Grunge layer and the Grunge Mask each choose a Projection Type, presented the same way as the Depth Volume decal's:

    Type Cost Behavior
    UV 1 fetch Follows the mesh texture coordinates. The default.
    Planar 1 fetch Projects from one direction (X, Y, or Z). Surfaces facing away from it stretch.
    Biplanar 2 fetches Blends the selected pair (XY, XZ, or YZ) using the surface normal.
    Triplanar 3 fetches Blends all three directions using the surface normal.

    Planar and Biplanar sample only their enabled axes, so they are genuinely cheaper than Triplanar rather than Triplanar with some weights zeroed. Projection Blend Sharpness applies to Biplanar and Triplanar only; Planar has nothing to blend between. Use Local Position stays available in every mode, because the breakup and streak noise are driven from that position even under UV mapping.

    Grunge follows height parallax in every projection type. UV mapping follows it through the displaced texture coordinates; the projected types are addressed by position instead, so parallax additionally publishes its displacement in world space and the projection position picks it up. This also covers the breakup and streak noise, which are position-addressed even under UV mapping.
